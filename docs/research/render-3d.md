# doplan: photorealistic 3D rendering (render-3d)

Status: research and decision record, 2026-11-12.
Stack targeted: Electron 45.3.1 (Chromium 156, Node 24 runtime), three 0.187.0 (r187), three-gpu-pathtracer 0.0.28, Windows first, dev box with an Intel Arc integrated GPU.

> How this was verified: package metadata from `npm view` on 2026-11-12, plus the source and JSDoc of the published tarballs `three@0.187.0` and `three-gpu-pathtracer@0.0.28`, which I read directly. Release notes come from the GitHub releases pages for r186 and r187 and the three-gpu-pathtracer CHANGELOG. Anything I could not verify is marked **(unverified)** or **(estimate)**.

## 0. TL;DR decisions

| # | Decision | Why (short) |
|---|---|---|
| D1 | **Use `WebGPURenderer` (`three/webgpu`) + TSL as the only renderer.** It uses the WebGPU backend, falls back to its built-in WebGL2 backend automatically, and `forceWebGL` can be set as a user toggle. Do **not** use classic `WebGLRenderer`. | In r186/r187 every interior-relevant feature lands only on WebGPURenderer: SSGI, stochastic SSR, TRAA/TAAU, `LightMapper`, GPU-baked `LightProbeGrid`, VXGI, box-projected env maps through TSL, OIT and ClusteredLighting. The path tracer has also moved: three-gpu-pathtracer **deprecated `WebGLPathTracer` in 0.0.25** and its new `WebGPUPathTracer` **requires r187**. |
| D2 | **Use vanilla three.js in an imperative `Engine` class.** React 19 handles only the editor UI. No react-three-fiber in the 3D viewport. | r3f 9.8 runs WebGPU only through an async `gl` factory. First-class WebGPU support is in r3f **10.0.0-alpha.6**. drei 10 is mostly WebGL/ShaderMaterial-based. Our scene is generated procedurally from a document model and needs tight control over on-demand rendering, bakes and the path-tracer lifecycle. |
| D3 | **Do not use pmndrs/postprocessing, n8ao or realism-effects.** Use the TSL `RenderPipeline` nodes that ship with three. | `postprocessing@6.39.6` is WebGL-only, with peer `three >=0.168 <0.188`, so it breaks at r188. n8ao depends on it. realism-effects was last published in **2023-05** and is dead. |
| D4 | **Interior lighting stack: physical light units, a baked `LightProbeGrid` for diffuse GI, `LightMapper` lightmaps on static architecture, per-room box-projected reflection probes, a DirectionalLight sun, and IES spots and RectAreaLights for fixtures.** HDRI is used for the outside view and sky, never as the main interior light. | Global IBL ignores occlusion and makes rooms look lit "from nowhere". Probe grids and lightmaps cost almost nothing at runtime, which is what makes an iGPU look good. |
| D5 | **Final render: `WebGPUPathTracer` from `three-gpu-pathtracer/webgpu` + `OIDNDenoiser` (oidn-webgpu 0.6.0) + optional `FSRUpscaler` (@pmndrs/upscaler 0.5.0).** | This path is maintained, has worker-built BVHs, area/IES/sun lights, transmission and SSS. |
| D6 | **Default tone mapping is `NeutralToneMapping`, with `AgXToneMapping` as a "cinematic" option. Do not offer ACES.** | Users choose paint and tile colours by swatch. Neutral keeps hue and saturation; ACES shifts hue and oversaturates. |
| D7 | **Build walls by our own 2D→3D extrusion: wall-elevation `Shape`s with opening holes, built per wall face.** CSG (`three-bvh-csg@0.0.18`) is a fallback only for exotic cuts, and it runs in a worker. | This gives exact UVs in metres, clean per-face material groups and no CSG robustness problems, and it is fast enough to rebuild on every edit. |
| D8 | **Procedural patterns (tiles+grout, herringbone, wallpaper half-drop) are generated by TSL and *baked into periodic textures*. Every surface then renders as a plain `MeshPhysicalNodeMaterial` with textures.** | The path tracer and LightMapper only understand standard and physical material properties and textures, not arbitrary TSL colour graphs. One code path serves raster, bake and path tracing. |
| D9 | **Asset pipeline: `@gltf-transform` 4.5.1 in a Node worker, using meshopt geometry compression (`EXT_meshopt_compression`) and KTX2 textures (UASTC for normal maps, ETC1S for everything else).** Draco is accepted on import only. | Meshopt decodes faster and has a smaller decoder. KTX2 cuts VRAM, which is critical on a shared-memory iGPU. |
| D10 | **On-demand rendering and adaptive DPR are mandatory.** Render only while the scene is dirty, plus N frames for temporal convergence. | An iGPU sharing the RAM bus, on battery, must not run at 60 fps while the scene is idle. |

## 1. WebGLRenderer vs WebGPURenderer in r187: feature matrix

Electron 45 ships Chromium 156 ([Electron 45 blog](https://www.electronjs.org/blog/electron-45-0), [endoflife.date](https://endoflife.date/electron)). On Windows, WebGPU runs on D3D12 via Dawn and has been enabled by default since Chrome 113. The DXC shader compiler has been the default since Chrome 121.

Verified by reading `three@0.187.0/examples/jsm` and `src`:

| Feature | WebGLRenderer (classic) | WebGPURenderer (TSL) | Notes |
|---|---|---|---|
| PBR `MeshPhysicalMaterial` (clearcoat, sheen, iridescence, anisotropy, EON rough diffuse r187, retroreflectivity r186) | yes | yes (`MeshPhysicalNodeMaterial`) | parity |
| Transmission (glass, sheer curtains) | yes | yes | parity (XR transmission fixes in r186) |
| PMREM | yes | yes (r187 replaced the CubeUV atlas with cube RTs on the WebGPU path) | parity |
| Shadows: PCF / VSM | yes. `PCFSoftShadowMap` deprecated in r186; use `PCFShadowMap` + `shadow.radius` | yes | parity |
| CSM | `examples/jsm/csm/CSM.js` | `CSMShadowNode`, `SunLight` + `SunLightNode` (r186) | SunLight docs say it is **not suited to single rooms or dioramas** |
| GTAO | `GTAOPass` (old EffectComposer) | `GTAONode` (r186/r187 fixes) | |
| SSAO | `SSAOPass`, `SAOPass` | `SSAONode` (r186, depth-aware blur) | |
| **SSGI** | **no** | `SSGINode` (GI + AO output, temporal, `resolutionScale` r187) | WebGPU-only |
| SSR | old `SSRPass` (mirror only) | `SSRNode`, **stochastic GGX mode**, F0/F90 MRT input, env MIS (r187) | WebGPU much better |
| **TRAA / TAAU** | `TAARenderPass` (static-camera supersampling only) | `TRAANode`, `TAAUNode` (temporal upscaling) | WebGPU-only for real TAA |
| Screen-space contact shadows | no | `SSSNode` | |
| Bloom | `UnrealBloomPass` | `BloomNode` | |
| **LightProbeGrid (irradiance volume)** | `LightProbeGridWebGL` | `LightProbeGrid`, **GPU-resident bake, multi-bounce, incremental** | WebGPU version is better |
| **LightMapper (diffuse lightmap baker)** | **no** | `LightMapper` (r187, WebGPU-only) | bakes probe-grid or VXGI irradiance into `uv1` |
| `unwrapUVs` (UV atlas for lightmaps) | geometry util (works for both) | same | r187 |
| VXGI (voxel cone-traced diffuse GI) | no | `VXGINode`, `VXGIVolume` (r186) | |
| ProgressiveLightMap | `misc/ProgressiveLightMap.js` | `misc/ProgressiveLightMapGPU.js` | superseded by LightMapper for our use |
| Box-projected env map (BPCEM) | no built-in (needs `onBeforeCompile` hacks) | `getParallaxCorrectNormal()` in TSL | key for interiors |
| Order-independent transparency | no | `OITPassNode` | glass shelves, tulle |
| Many lights | forward, every light per fragment | `ClusteredLighting` (Forward+) | apartments with 30+ downlights |
| IES lights | no | `IESSpotLight` | |
| Path tracer (three-gpu-pathtracer) | `WebGLPathTracer` (**deprecated since 0.0.25**) | `WebGPUPathTracer` (requires r187) | |
| Ecosystem (pmndrs/postprocessing, n8ao, drei shader materials) | yes | no | we do not need them |
| Meshlets / visibility buffer | no | r187 `MeshletDrawingPipeline`, `VisibilityBufferDrawingPipeline` | not needed for interiors; possible later |

**Conclusion.** For interiors, WebGPURenderer is the only renderer that still gets features: three's own manual says there are no plans to add larger new features outside WebGPURenderer. Its WebGL2 fallback backend keeps the app running on machines where WebGPU fails. Raster effects compile TSL to GLSL; the path tracer and `LightProbeGrid.bake()` still need WebGPU. **Risk:** the TSL APIs still churn: `PostProcessing` was renamed to `RenderPipeline` in r183 (old name still exported as a wrapper), and `getProjectionDepth` became `projectionDepth` in r187. Mitigation: pin `three` exactly (`"three": "0.187.0"`), keep all three-specific code under `src/renderer/engine/**`, and upgrade deliberately each release.

## 2. Architecture: vanilla three, not r3f

```
React UI (panels, inspector, catalog)  <-- zustand store -->  Engine (vanilla TS)
                                                               |- SceneBuilder (doc -> meshes, incremental)
                                                               |- MaterialLibrary (shared materials/textures, TSL uniforms)
                                                               |- LightingSystem (sun, fixtures, probes, bakes)
                                                               |- RenderPipeline (preset-driven TSL post graph)
                                                               |- PathTraceSession (WebGPUPathTracer lifecycle)
                                                               '- FrameScheduler (on-demand + adaptive DPR)
```

- The engine subscribes to store slices: `store.subscribe(selector, onChange)`. A change marks affected *entities* dirty, and `SceneBuilder` rebuilds only those (one wall, one room floor). It never re-renders React to rebuild the scene.
- Why not r3f:
  - r3f 9.8.2 supports WebGPU only through the async `gl` factory.
  - r3f 10 (first-class WebGPU, `state.renderer`) is still `10.0.0-alpha.6`.
  - Our object graph comes from the plan document, not hand-authored JSX.
  - We need explicit control of `setAnimationLoop`, bake passes, and swapping the canvas to the path tracer.
  - Most of drei's "pretty" components (MeshReflectorMaterial, MeshTransmissionMaterial, AccumulativeShadows, N8AO) are WebGL ShaderMaterials, so they are unusable with D1 anyway.
- The 3D viewport is one `<canvas>` owned by the engine and mounted into a React `div` via a ref.

## 3. Renderer setup (all presets)

```ts
// src/renderer/engine/createRenderer.ts
import { WebGPURenderer, NeutralToneMapping, PCFShadowMap, HalfFloatType } from 'three/webgpu';

export async function createRenderer(canvas: HTMLCanvasElement, opts: { forceWebGL?: boolean }) {
  const renderer = new WebGPURenderer({
    canvas,
    antialias: false,            // AA comes from TRAA / SMAA / FXAA in the pipeline (TRAA forbids MSAA)
    forceWebGL: opts.forceWebGL ?? false,
    powerPreference: 'high-performance',
    outputBufferType: HalfFloatType, // default; HDR intermediate
    trackTimestamp: true,        // GPU timings for adaptive DPR and path tracer adaptive budget
    reversedDepthBuffer: true,   // better depth precision; falls back gracefully
  });
  await renderer.init();         // REQUIRED before KTX2Loader.detectSupport / LightProbeGrid.bake
  renderer.toneMapping = NeutralToneMapping;
  renderer.toneMappingExposure = 1.0;   // driven by an EV control, see section 4.1
  renderer.shadowMap.enabled = true;
  renderer.shadowMap.type = PCFShadowMap;  // PCFSoft is deprecated (r186)
  renderer.onDeviceLost = (info) => engine.handleDeviceLost(info);   // section 9.6
  return renderer;
}
```

Electron main process:

```ts
// On dual-GPU laptops, prefer the discrete GPU. Keep the Chromium GPU blocklist ON.
app.commandLine.appendSwitch('force_high_performance_gpu');
// Do NOT set 'enable-unsafe-webgpu' or 'ignore-gpu-blocklist' in production.
// Expose a "Use compatibility renderer (WebGL2)" setting -> forceWebGL: true.
```

Detect the backend at runtime with `renderer.backend.isWebGPUBackend`. If it is false, disable the Path-traced preset and `LightProbeGrid.bake()`. Lightmaps baked earlier and saved in the project file still load and display.

## 4. Lighting interiors photorealistically (raster)

### 4.1 Units and exposure
- Use physical units throughout. Light intensities are in candela/lumens; three's lights are physical since r155.
  - LED downlight: 400–800 lm, 2700–4000 K.
  - Sun: about 100,000 lux direct.
  - Overcast sky: about 10,000 lux.
- Expose an **EV100** control and map it to `toneMappingExposure = 1 / (1.2 * 2^EV100)`, scaled by a calibration constant tuned once against reference renders.
  - Interior daylight looks right around EV 6–8; night with lamps around EV 3–5.
  - Add "auto exposure" later by reading back average luminance from a downsampled pass.
- Store colour temperature in the document and convert it to RGB with a Kelvin→sRGB table.

### 4.2 Direct light
- **Sun:** one `DirectionalLight`. Set its direction from the geo location, date and time (SunCalc-style maths, about 100 lines, no dependency) and fit its orthographic shadow camera to the apartment's bounding box.
  - Do **not** use `SunLight`/CSM for apartments (three's own doc warns against it for single rooms).
  - Shadow map: 2048 (Low) or 4096 (High). `shadow.radius` 2–4, `normalBias` 0.02.
  - Physically, the sun only reaches a room through windows, so walls and slabs must cast shadows. Model the **exterior shell closed**: a ceiling slab with thickness, plus the floor slab.
- **Fixtures:**
  - Spots and downlights: `IESSpotLight` with bundled IES profiles. Only the 2–4 most important fixtures cast shadows; the rest are unshadowed. Use `ClusteredLighting` when there are more than about 16 lights.
  - LED panels and linear lights: `RectAreaLight` (raster area lights have no shadows; acceptable for panels).
  - Lamps and pendants: `PointLight` (no shadow on Low) plus an emissive lampshade material.
- **Window "sky fill":** an invisible `RectAreaLight` in each window opening, facing inward, coloured by the sky. It fakes the sky dome entering through the window and is the single biggest realism win on Low quality. Intensity comes from sky luminance × window area.

### 4.3 Indirect diffuse (GI): baked, not screen-space, as the foundation
1. **`LightProbeGrid` per apartment level** (`three/addons/lighting/LightProbeGrid.js`):
   - Grid spacing about 0.5–0.75 m: for example 12 m × 2.8 m × 10 m → 20×4×16 = 1,280 probes.
   - `cubemapSize: 8`, `bounces: 2`.
   - The bake is fully on the GPU and incremental (`start`/`count`), so it can run in time slices of about 32 probes per frame without freezing the UI.
   - Re-bake (debounced 500 ms) after wall, opening or light edits. The grid is a `Light`, so adding it to the scene lights every node material.
   - Use priority/multiple grids for multi-level plans and balconies.
2. **`LightMapper` lightmaps on static architecture** (walls, floors, ceilings, built-ins) for High and final export:
   - Run `unwrapUVs(roomGroup, { attribute: 'uv1', texelsPerUnit: 32 })` and keep its padding of 4 or more.
   - Bake with irradiance = `lightProbeGridIrradiance(probes, …)` and the sun plus shadowed fixtures in `lights`. Use ≤256 samples (half-float accumulation limit).
   - At runtime, keep baked contributions out of dynamic lighting (the double-counting rule in the LightMapper docs).
   - Furniture and other movable objects receive probe-grid lighting only.
3. **SSGI** (High only) adds short-range dynamic bounce and colour bleeding on top of the baked base.

### 4.4 Indirect specular (reflections)
- **Per-room reflection probe:**
  - Place a `CubeCamera` at the room centre at 1.2 m height. Render once after edits at 256² (Low) or 512² (High), then PMREM it.
  - Use **box projection** in the material's env node:
    ```ts
    import { reflectVector, pmremTexture, uniform } from 'three/tsl';
    import { getParallaxCorrectNormal } from 'three/tsl'; // exported via TSL.js in r187
    const boxSize = uniform(new Vector3(w, h, d)), boxPos = uniform(roomCenter);
    material.envNode = pmremTexture(roomProbeRT.texture, getParallaxCorrectNormal(reflectVector, boxSize, boxPos));
    ```
  - Every material inside the room gets that room's probe. Assign by room id from the plan's room polygons; a point-in-polygon test on the object's position handles furniture.
- **SSR** (High), for glossy floors, tiles and mirrors: `ssr(..., { stochastic: true, roughnessNode, metalnessNode, specularNode: specularColorBlended MRT })` with TRAA as the denoiser. Mirrors can also be planar reflections (`reflector()` TSL node), and that is cheaper on Low.

### 4.5 HDRI environment
- Poly Haven HDRIs are CC0. Load them with `HDRLoader` (RGBELoader was replaced in recent three) and use them for:
  - `scene.background`, seen through windows. For an interior camera, use a ground-projected or skybox variant.
  - The exterior lighting source for probe bakes.
- Set `scene.environmentIntensity` low (0.0–0.2) indoors, because the room probes carry specular. This avoids light leaks.

## 5. Post stack (TSL `RenderPipeline`)

```ts
import { RenderPipeline } from 'three/webgpu';
import { pass, mrt, output, normalView, velocity, metalness, roughness, directionToColor, colorToDirection, vec4 } from 'three/tsl';
import { ssgi } from 'three/addons/tsl/display/SSGINode.js';
import { ssr } from 'three/addons/tsl/display/SSRNode.js';
import { traa } from 'three/addons/tsl/display/TRAANode.js';
import { ao } from 'three/addons/tsl/display/GTAONode.js';
import { bloom } from 'three/addons/tsl/display/BloomNode.js';
import { smaa } from 'three/addons/tsl/display/SMAANode.js';
```
Helper signatures checked in the r187 source: `ao(depth, normal, camera)`, `ssgi(beauty, depth, normal, camera)`, `ssr(color, depth, normal, options)`, `traa(beauty, depth, velocity, camera)`, `bloom(node, strength, radius, threshold)`, `smaa(node)`. The snippets below are sketches; the composite maths must be validated in R1/R4. The node files exist in r187: `SSGINode, SSRNode, TRAANode, TAAUNode, GTAONode, SSAONode, BloomNode, SMAANode, FXAANode, SSSNode, DenoiseNode, OITPassNode`.

### Preset LOW (Intel Arc iGPU, 1080p–1440p, target 60 fps orbit)
```ts
renderer.setPixelRatio(Math.min(devicePixelRatio, 1.0)); // adaptive 0.6–1.0 while moving
sun.shadow.mapSize.set(2048, 2048); fixtures: castShadow=false
// baked: LightProbeGrid (bounces 1), room reflection probes 256², no lightmaps at runtime unless already baked
const scenePass = pass(scene, camera);
scenePass.setMRT(mrt({ output, normal: directionToColor(normalView) }));
const aoPass = ao(scenePass.getTextureNode('depth'), colorToDirection(scenePass.getTextureNode('normal')), camera);
aoPass.resolutionScale = 0.5; // half-res GTAO
const lit = scenePass.getTextureNode('output').mul(aoPass.getTextureNode().r);  // apply AO to indirect only if possible
pipeline.outputNode = smaa(renderOutput(lit)); // tone map + sRGB, then SMAA (no temporal ghosting on iGPU)
// no SSGI, no SSR, no bloom
```

### Preset HIGH (discrete GPU or strong iGPU when idle)
```ts
renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5));
sun.shadow.mapSize.set(4096, 4096); 2–4 fixture shadows; ClusteredLighting if >16 lights
// baked: LightProbeGrid bounces 2 + LightMapper lightmaps for architecture; probes 512²
scenePass.setMRT(mrt({ output, normal: directionToColor(normalView), velocity, metalrough: vec4(metalness, roughness, 0, 1) /* + specularColorBlended */ }));
const gi = ssgi(color, depth, normal, camera);  gi.sliceCount.value = 2; gi.stepCount.value = 8; // "Medium, temporal"
gi.radius.value = 3; // metres-ish in our units; interiors need a small radius
const refl = ssr(color, depth, normal, { stochastic: true, roughnessNode, metalnessNode, camera });
const composite = color.add(gi.getGINode().mul(albedo)).mul(gi.getAONode().r).add(refl);
const bloomed = composite.add(bloom(composite, 0.15 /*strength*/, 0.4 /*radius*/, 0.9 /*threshold (HDR)*/));
pipeline.outputNode = traa(renderOutput(bloomed), depth, velocityTex, camera); // TRAA also denoises SSGI/SSR
```
- Temporal effects need about 8–16 frames to converge. The scheduler keeps rendering 24 frames after the last change (section 9.4).
- The SSGI docs say not to drop `resolutionScale` below 0.5; drop DPR first.

### Preset PATH-TRACED (stills; section 6)
The raster pipeline is suspended, and `WebGPUPathTracer` takes over the canvas or an offscreen target.

### Preset comparison
| | Low (iGPU) | High | Path-traced |
|---|---|---|---|
| DPR | adaptive 0.6–1.0 | 1.0–1.5 | renderScale 0.5 preview / 1.0 final |
| AA | SMAA | TRAA | progressive + OIDN |
| GI | probe grid (1 bounce) | probe grid (2) + lightmaps + SSGI | full path tracing |
| AO | GTAO ½ res | SSGI AO | path traced |
| Reflections | box-projected probes, planar mirror | probes + stochastic SSR | path traced |
| Shadows | sun 2048 | sun 4096 + 2–4 fixtures | exact, soft (SunLight/area) |
| Bloom | off | subtle | optional post on output |
| Max texture size | 1024 | 2048 | 4096 |

**(estimate)** Low should hold 45–60 fps at 1080p on an Arc-class iGPU for a 3-room apartment with about 150 furniture items. This must be benchmarked in M1; the numbers are not measured.

## 6. Final render: three-gpu-pathtracer 0.0.28

Facts from the 0.0.28 package source, the CHANGELOG and `src/webgpu/API.md`:
- Exports: `three-gpu-pathtracer/webgpu` → `WebGPUPathTracer, BlurredEnvMapGenerator, OIDNDenoiser, FSRUpscaler, RenderToScreenMaterial`. The root export still has the deprecated `WebGLPathTracer` and `PhysicalCamera, EquirectCamera, PhysicalSpotLight, ShapedAreaLight`.
- Peer dependencies: `three >=0.187.0`, `three-mesh-bvh >=0.9.17` (0.9.18 is current; **pin it exactly**, because the README says the WebGPU tracer is not yet stable and depends on changing BVH APIs), `xatlas-web ^0.1.0`.
- Lights: RectArea (rect + circular), Spot (with `iesMap`), Point, Directional, **SunLight** (0.0.27), and environment.
  - Area lights accept `visibleToCameraRays = false` (0.0.27).
  - Lights are sampled by estimated contribution (0.0.27).
  - MIS is on by default.
- Materials: properties of `MeshStandardMaterial`/`MeshPhysicalMaterial`: transmission, clearcoat, sheen, iridescence, dispersion, plus volumes/SSS (0.0.28) and fog volumes.
  - **Custom TSL colour graphs are not traced**, which is why D8 bakes patterns into textures.
  - Textures are packed into an RGBA8 atlas on the GPU, so KTX2-compressed source textures are fine.
  - InstancedMesh and BatchedMesh, including per-instance colours, are handled.
- Scene build: `setSceneAsync` + `setBVHWorker(GenerateMeshBVHWorker)` builds BVHs in workers (0.0.28). After edits, call `updateMaterials / updateTransforms / updateCamera / updateLights / updateEnvironment`; geometry changes need a new `setScene`.
- Options: `maxBounces` (default 15), `maxSamples`, `frameBudget` (path steps per `renderSample`), `renderScale`, `filterGlossyFactor`, `clampIndirect` (10), `dynamicLowRes`, `lowResScale`, `adaptiveFrameBudget` + `targetFrameTime` (needs `trackTimestamp`), `randomStrategy` (Sobol default), `renderToCanvas`, `synchronizeRenderSize`, `setSize()`.
- Events: `progress` (stages building/compiling/rendering/denoising, with sample counts) and `complete`.
- Denoise: `OIDNDenoiser({ initUNetFromURL, auxWeightsUrl, useAuxiliaryBuffers, maxTileSize, dynamicTile })` from `oidn-webgpu@0.6.0`.
  - It runs after accumulation stops (`maxSamples > 0`) and is tiled across frames.
  - Weights come from the oidn-weights repo in `_small` and `_large` variants.
  - **Bundle the weights in the app** (`resources/oidn/*.tza`) and load them via a `file:`/custom-protocol URL. Never fetch them at runtime.
- Upscale: `FSRUpscaler` + `@pmndrs/upscaler@0.5.0` allows `renderScale: 0.5` previews that look sharp.
- Tiles: the tracer has no tile mode; `frameBudget` bounds per-frame work instead, which keeps the UI responsive and avoids Windows TDR resets. The denoiser is tiled.
- There is **no lightmap-baking API** in the tracer. Use three's `LightMapper` for bakes.
- **The tracer requires a WebGPU device, so it does not run on the WebGL2 fallback.** Grey out the preset there.

### Recommended final-render session

```ts
import { WebGPUPathTracer, OIDNDenoiser, FSRUpscaler } from 'three-gpu-pathtracer/webgpu';
import { GenerateMeshBVHWorker } from 'three-mesh-bvh/worker';
import { initUNetFromURL } from 'oidn-webgpu';

const pt = new WebGPUPathTracer(renderer);
pt.setBVHWorker(GenerateMeshBVHWorker);
pt.maxBounces = 10;            // interiors need more than 5; 8–12 is the sweet spot
pt.maxTransparentBounces = 8;
pt.filterGlossyFactor = 0.5;   // kills fireflies from small bright sources via glossy paths
pt.clampIndirect = 10;         // default; lower (5) for previews
pt.renderToCanvas = true;
pt.dynamicLowRes = true; pt.lowResScale = 0.25;  // interactive preview while orbiting
pt.adaptiveFrameBudget = true; pt.targetFrameTime = 16;
pt.setDenoiser(new OIDNDenoiser({ initUNetFromURL, auxWeightsUrl: oidnUrl('rt_hdr_alb_nrm_large'), useAuxiliaryBuffers: true, maxTileSize: 512 }));
await pt.setSceneAsync(ptScene, camera);    // ptScene = render scene with PT-specific swaps (below)
pt.maxSamples = quality === 'draft' ? 128 : quality === 'final' ? 1024 : 4096;
pt.addEventListener('progress', e => ui.setProgress(e.stage, e.progress, e.samples));
pt.addEventListener('complete', () => exportImage());
// loop: renderer.setAnimationLoop(() => pt.renderSample());
```

Export at a resolution other than the window: set `synchronizeRenderSize = false`, call `setSize(3840, 2160)` and `renderToCanvas = false`, then read `pt.target` via `renderer.readRenderTargetPixelsAsync` (or draw it to an offscreen canvas) and encode PNG/JPEG/EXR in a worker. **(unverified)** The exact readback path for the `target` StorageTexture should be prototyped in M-PT1.

### Lighting interiors for the path tracer
- **Sun through windows:** swap the realtime `DirectionalLight` for a `SunLight`, which supports angular size and therefore soft shadows in the tracer. Use the HDRI or `GradientEquirectTexture` sky as the environment.
- **Window "portals":** three-gpu-pathtracer has **no true light portals**. Environment light through a small window converges slowly. Mitigations:
  1. Model window glass as thin transmission: `transmission: 1, thickness: 0, ior: 1.5, roughness: 0`. Or hide glass panes in path-traced mode, which is the cheapest way to get fast convergence. Make this a render option.
  2. Add a `RectAreaLight` in each window opening with `visibleToCameraRays = false`, coloured by the sky. It is not energy-exact (it double-counts with the environment), so reduce `environmentIntensity` and expose a "window fill" slider.
  3. Raise `minSamples`/`maxSamples` and rely on OIDN.
- **Ceiling lights:** `IESSpotLight`/`PhysicalSpotLight` with `iesMap` for downlights, `RectAreaLight` for panels, and emissive meshes only for visible lamp surfaces. Emissive meshes are not MIS-sampled, so they cause noise when used as the main light.
- **Clamp fireflies** with `clampIndirect` + `filterGlossyFactor`. Avoid tiny, very bright emissive meshes.
- **(estimate)** On the Arc iGPU, a 1080p draft with 128 spp + OIDN takes about 1–3 min and a 4K final with 1024 spp takes 20–60 min. On a discrete RTX-class GPU it is 5–10× faster. Benchmark in M-PT1, and show an ETA from `getSampleCountsAsync().samplesPerSecond`.

## 7. Geometry generation

### 7.1 Walls with openings (decision D7)
Input is the wall graph from the 2D plan: nodes and wall segments with thickness, height, and openings (offset along the wall, width, sill height, head height).

1. **Footprint:** for each wall, compute the two offset lines (±t/2). At each node, intersect neighbouring walls' offset lines, sorted by angle, to get mitred corner points. This gives each wall's side-A and side-B lengths and its end caps.
   - Use the same algorithm the 2D editor uses for the plan fill, so 2D and 3D always match.
   - Use `clipper2-js` or our own code for robust offsets.
2. **Each face** (side A, side B) is a `THREE.Shape` in **wall-local 2D coordinates**: u = metres along the face from its start corner, v = metres above the finished floor.
   - The outline is a polygon. Sloped ceilings and attic walls are supported by making the top edge non-horizontal.
   - Openings become `shape.holes`.
   - Arches: use `absarc`/`quadraticCurveTo` in the hole path.
   - Triangulate with `ShapeUtils.triangulateShape` (earcut), then place vertices with `origin + u*dir + v*up`. **UV = (u, v) in metres for free.**
3. **Reveals:** for each opening, add jamb, head (lintel) and sill quads spanning the wall thickness, with UVs in metres. They get their own material slot (paint by default, matching the face material). Window sills are separate parametric objects.
4. **Top cap and end caps** are simple quads, hidden under the ceiling but needed for the section view and for clean shadows.
5. **Per-face material groups:** each face can be split horizontally (wainscot or tile apron height, e.g. tiles to 1.2 m, paint above) and vertically (accent segment). The split is done on the 2D shape before triangulation, so every region is one geometry group with its own `materialIndex`.
6. Merging: one `BufferGeometry` per **room-surface set** (all faces of room R), with groups pointing into a per-room material array. This keeps draw calls at about 3–6 per room and lets a single wall rebuild in under 1 ms.

**CSG (`three-bvh-csg@0.0.18`, peer `three >=0.179`)** is used only for:
- cuts through curved or freeform walls;
- niches and recesses that do not go through the wall;
- custom kitchen countertop cut-outs on imported meshes.

Run it in a worker, cache the results, and never use it on the hot edit path. Curved walls are approximated by N straight segments (chord error < 5 mm) and use the same face builder.

### 7.2 Floors and ceilings
- Room polygons come from the planar wall graph: compute faces of the arrangement and take the inner offset loops.
- **Floor:** a `ShapeGeometry` of the room's inner polygon at y = 0 (plus floor build-up thickness). UV = world XZ in metres; rotation and offset are applied in the material (parquet direction).
  - Door thresholds: extend the floor under the door leaf to the wall centreline. A threshold strip is shown when the two rooms' floor materials differ.
- **Ceiling:** the same polygon at the room height, flipped.
  - Drop ceilings, soffits and coves are extrusions of sub-polygons (`ExtrudeGeometry` with `depth`, `bevelEnabled: false`), plus an optional LED cove `RectAreaLight`/emissive strip.
- **Slabs:** the floor and ceiling slab of the whole apartment shell (thickness 0.2 m) keep light out in bakes and the path tracer.

### 7.3 Skirting boards and cornices
- Write our own `sweepProfile(path: Vec2[], closed: boolean, profile: Vec2[], up: Vec3)`.
  - Mitre at each path vertex by intersecting the offset profile planes, so there is **no Frenet twisting** (avoid `ExtrudeGeometry({ extrudePath })`).
  - U = cumulative path length in metres; V = profile arc length.
- **Skirting:** the path is the room's inner loop, **broken at door openings**, with end caps where it is broken.
- **Cornice:** the inner loop at ceiling height, unbroken.
- Profiles are a library of 2D polylines in millimetres (ogee, bullnose, flat 80/100/120, shadow-gap), editable as JSON.

### 7.4 Tile patterns with grout (decision D8)
- `PatternBaker` renders TSL into a **periodic texture set** (baseColor, normal, roughness/AO packed ORM), at about 256 px per metre for Low and 512 px/m for High and the path tracer.
- Pattern math (on UV in metres) gives a tile cell id, a local tile coordinate and the distance to the nearest grout edge:
  - **grid / stacked**: `cell = floor(uv / size)`;
  - **running bond (brick)**: shift x by `offset*(row mod 2)` (1/2, 1/3, 1/4 bond);
  - **herringbone**: rotate 45°, then use a 2-tile L-shaped period (the classic period-2 lattice); **chevron**: angled tiles meeting at a mitre line;
  - **hex**: axial hex coordinates (cube rounding);
  - **basketweave and versailles** follow later from the same framework.
- Grout:
  - The width is in millimetres.
  - The mask is `smoothstep` on the edge distance, scaled by a pixel-footprint derivative to avoid aliasing.
  - The grout colour and roughness are separate.
  - The normal bevel comes from the edge-distance gradient, and the grout gets a little extra AO darkening in the baked ORM.
- **Per-tile variation:** a hash of the cell id selects a source sub-texture or offset from the tile's photo texture set, giving natural variation of marble or wood planks. It also adds a small random hue/brightness/roughness jitter and lippage (normal tilt).
- **Period:**
  - The baked texture covers an integer number of pattern periods (e.g. 4×4) and is tiled with `RepeatWrapping`. That size is enough to hide repetition from per-tile randomness.
  - Herringbone and chevron periods are computed analytically.
  - Hex uses a rectangular super-period (√3 ratio), with the texture's pixel size chosen accordingly.
- The material's UV transform in TSL is `uv().sub(origin).rotate(angle).div(periodSizeMeters)`. It is a per-material uniform, so one baked texture serves all surfaces with the same tile spec.
- The **start point** (tile layout origin, e.g. centred on the room or starting at a door) is a property of the surface, shown in the editor as a gizmo.

### 7.5 Wallpaper
- Physical parameters: roll width (e.g. 0.53 m or 1.06 m), pattern repeat height, and match type (straight / half-drop / random/free).
- Half-drop is baked into a 2-roll-wide period texture (the right column shifted by repeat/2). UV origin is at a wall corner or the wall centre (user choice).
- Optional seam lines (subtle normal), and paper or vinyl roughness.

### 7.6 Paint
- Paint is a `MeshPhysicalNodeMaterial` with the colour from a palette and a sheen level (matte, eggshell, satin, gloss) that maps to roughness 0.9 / 0.6 / 0.45 / 0.2 and clearcoat 0 / 0 / 0.1 / 0.4.
- Ship RAL Classic / NCS-like palettes as RGB approximations **(licence check: palette names may be trademarked, use our own names plus the hex value)**.

### 7.7 Curtains and blinds (procedural)
- **Curtain panel:** a grid of (columns × rows) vertices along the rail.
  - x(t) follows the rail. The z-displacement is a sum of sines: pleat count = `round(width*fullness / pleatSpacing)`, with fullness 1.5–2.5×.
  - Amplitude grows slightly toward the hem; add small noise.
  - Header styles (pinch pleat, eyelet, wave) change the top-row amplitude and pattern. A tied-back variant uses a smooth bend toward the tie point (quadratic Bézier along the height).
  - Compute normals analytically; UV in metres of flat fabric (arc length), so fabric textures do not stretch.
- **Materials:**
  - Opaque fabric: `MeshPhysicalNodeMaterial` with `sheen` 0.5–1, `sheenRoughness` 0.5, double-sided.
  - Sheer or tulle: `transmission` 0.6–0.9, `thickness` 0, `roughness` 0.6. Alpha-tested weave textures are cheaper on Low; Low uses `opacity` with OIT if needed.
- **Roller, roman and venetian blinds:** parametric (box, folded stack, instanced slats with `InstancedMesh`).

### 7.8 Parametric windows and doors
- Windows are defined by a parameter object: frame profile (2D polyline), sash layout (fixed, casement, tilt, sliding), mullions/transoms, glass thickness, sill in/out, and colour inside/outside (two materials).
  - The frame members are built with `sweepProfile` around rectangles. Glass is a thin box, or a single quad with thin transmission.
  - The **same param object defines the wall hole** (via 7.1), so they can never disagree.
- Doors work the same way, with leaf styles (flush, panelled via profile sweep, glazed), architrave profile sweep, handle (glTF asset) and swing (open-angle parameter for renders).
- Cache generated meshes by a parameter hash. Identical windows become `InstancedMesh` instances.

## 8. Assets: glTF pipeline and runtime budgets

### 8.1 Ingest pipeline (main process / Node worker)
Formats accepted: glTF/GLB (native), plus FBX/OBJ via three loaders in a hidden worker, which convert to glTF first.

```ts
// @gltf-transform/core|functions|extensions 4.5.1 + meshoptimizer 1.3.0
import { NodeIO } from '@gltf-transform/core';
import { ALL_EXTENSIONS } from '@gltf-transform/extensions';
import { dedup, prune, weld, resample, simplify, textureCompress, meshopt, center, quantize } from '@gltf-transform/functions';
import { MeshoptEncoder, MeshoptSimplifier } from 'meshoptimizer';

await doc.transform(
  center({ pivot: 'below' }),     // furniture sits on the floor at y=0
  dedup(), prune(), weld(),
  simplify({ simplifier: MeshoptSimplifier, ratio: 1.0, error: 0.0005 }), // clean only; LODs below
  textureCompress({ targetFormat: 'webp', resize: [2048, 2048] }),         // intermediate
  meshopt({ encoder: MeshoptEncoder, level: 'medium' }),                   // EXT_meshopt_compression + quantization
);
```
- **KTX2:**
  - Use the KTX-Software `ktx` CLI, bundled as a resource binary (Apache-2.0), via `@gltf-transform/cli`'s `ktx` path or by spawning `ktx create` ourselves.
  - BaseColor and ORM → ETC1S (Basis LZ, small). Normal maps → UASTC + zstd.
  - Keep WebP as the fallback inside the asset package.
- **LODs:** use `simplify` at ratio 0.5 and 0.15 into separate files `asset.lod1.glb` and `asset.lod2.glb`. They are used for the overview/doll-house camera and for thumbnails of large scenes.
- **Metadata** stored next to the GLB as `asset.json`: real-world bounding box (verify the scale is in metres, rescale on import), category, mount type (floor / wall / ceiling / countertop), material slots that can be recoloured, licence and source URL, and a thumbnail (rendered offscreen at 256² by the engine).
- Runtime loaders: `GLTFLoader` + `MeshoptDecoder` (`three/addons/libs/meshopt_decoder.module.js`) + `KTX2Loader` (call `detectSupport(renderer)` after `await renderer.init()`) + `DRACOLoader` (import compatibility). Serve the Basis/Draco wasm from app resources.

### 8.2 Runtime budgets
| | Low (iGPU) | High |
|---|---|---|
| Max texture size (per-preset downscale on load) | 1024 | 2048 (4096 path-traced) |
| Texture VRAM budget (KTX2) | ~1 GB | ~2.5 GB |
| Triangles in view | ≤ 3 M | ≤ 10 M |
| Draw calls | ≤ 800 | ≤ 2,500 |

- Identical assets become **`InstancedMesh`**, grouped per asset per material (chairs around a table, downlights, slats). Mixed small static props (books, decor) use `BatchedMesh`. The path tracer supports both.
- Frustum culling is the default (`object.frustumCulled`), with per-mesh bounding spheres. Occlusion culling is not needed for single apartments.
- Material dedup: `MaterialLibrary` keys materials by (texture set id, params hash), so 40 identical oak floors share one material and textures. Per-instance tint goes through `instanceColor`.
- Dispose aggressively. On scene unload, call `geometry.dispose()`, `material.dispose()` and `texture.dispose()`, and track reference counts in `MaterialLibrary`.

### 8.3 Open asset sources (for the assets workstream)
- Poly Haven: HDRIs, PBR textures and models, **CC0**.
- ambientCG: PBR textures, **CC0**.
- Kenney furniture packs: **CC0**, low-poly; useful for blockout.
- Licences must be re-verified per item at download time by the asset agent.

## 9. Performance and robustness in Electron

### 9.1 On-demand rendering (FrameScheduler)
```ts
class FrameScheduler {
  private dirtyUntil = 0;
  invalidate(frames = 1) {          // call on any scene, camera or material change
    this.dirtyUntil = Math.max(this.dirtyUntil, this.frame + frames + this.temporalTail);
    if (!this.running) { this.running = true; this.renderer.setAnimationLoop(this.tick); }
  }
  private tick = () => {
    this.frame++;
    this.pipeline.render();
    if (this.frame >= this.dirtyUntil) { this.renderer.setAnimationLoop(null); this.running = false; }
  };
}
// temporalTail = 0 on Low (no temporal effects), 24 on High (TRAA/SSGI convergence)
```
OrbitControls `change` → `invalidate()`. Bakes and the path tracer run their own loops, and the scheduler yields to them.

### 9.2 Adaptive DPR
- While the camera moves, use `dprMoving` (Low 0.6, High 0.85). When idle for 150 ms, refine to `dprIdle` (Low 1.0, High 1.5) and render the temporal tail.
- With `trackTimestamp: true`, read the GPU time (`renderer.info.timestamp` / `resolveTimestampsAsync`). If the median of the last 30 frames is above 20 ms, step `dprMoving` down by 0.1; if below 10 ms, step it up.
- On High, `TAAUNode` can upscale from DPR 0.7 to 1.0 output.

### 9.3 Shader/pipeline compile hitches
- Call `await renderer.compileAsync(scene, camera)` after scene load and after material-library changes. r187 compiles pipelines in parallel.
- Keep material *variants* low: shared node materials where only uniform values differ, not new node graphs per colour.

### 9.4 Background and visibility
- Keep Electron's default `backgroundThrottling: true`.
- Stop the animation loop when `document.hidden`, except during a path-trace or bake job. During those jobs, call `powerSaveBlocker.start('prevent-app-suspension')` from main.

### 9.5 Memory
- Use the WebGPU backend's half-float output.
- Release render targets of disabled passes when switching presets (rebuild the `RenderPipeline` graph and call `.dispose()` on the old nodes).

### 9.6 Device and context loss
- WebGPU: `renderer.onDeviceLost = info => …`, wired to `device.lost` in r187's backend. GPU resets are not rare on Windows TDR, especially during long path traces on an iGPU. The handler:
  1. shows a "GPU reset, restoring…" toast;
  2. calls `renderer.dispose()` (async in r186+);
  3. creates a new renderer with `createRenderer()`;
  4. re-uploads — the scene graph and CPU-side geometry stay intact;
  5. reloads baked lightmaps and probe data from the project cache (bakes are persisted, section 9.7).
- WebGL2 fallback: the same path through `webglcontextlost` / `webglcontextrestored`.
- Path tracer TDR avoidance: keep `frameBudget` small (`adaptiveFrameBudget` with `targetFrameTime` 16–33 ms). Never dispatch seconds of work in one submit.

### 9.7 Persist bakes
- Store the `LightProbeGrid` atlas (RGBA half-float 3D texture), lightmaps (EXR or KTX2 RGBA16F) and room reflection probes in the project folder under `cache/bake/<hash>`. The key is a hash of the geometry, lights and materials that affect lighting.
- On reopen, the scene shows baked lighting immediately, and the WebGL2 fallback can display bakes it cannot produce itself.

## 11. Risks

| Risk | Mitigation |
|---|---|
| TSL/WebGPURenderer API churn (renames every few releases) | Pin `three@0.187.0` exactly. Isolate the engine. Upgrade one release at a time with the reference-scene screenshot diff. |
| `WebGPUPathTracer` is marked unstable and pins BVH APIs | Pin `three-gpu-pathtracer@0.0.28` + `three-mesh-bvh@0.9.18` exactly. The path tracer is optional; the app is fully usable without it. |
| WebGPU driver bugs on some Intel/AMD iGPUs | Provide a `forceWebGL` setting plus automatic fallback when `init()` fails. Persisted bakes keep the fallback looking good. |
| LightMapper is new (r187), so edge cases are likely | Lightmaps are a High-preset enhancement only. The probe grid alone is the baseline. |
| Light leaks at wall/floor junctions in bakes | Closed shell (slabs), wall top caps, thickness-aware probe placement (probes inside walls are invalid; nudge them or use a grid per room), small `normalBias`. |
| Long path traces trip Windows TDR | `adaptiveFrameBudget`, `onDeviceLost` restore, checkpoint the accumulated image every N samples. |
